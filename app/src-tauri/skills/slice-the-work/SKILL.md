# Slice the work

Slice across, not by layer. "The database part" cannot be checked by anyone. "Sen can see their own tickets, unfiltered" can.

1. **Read the brief** and the code or screens it touches, if you may.
2. **Find the thinnest thing that works from end to end.** That is slice one, even if it looks plain. Each next slice adds one thing a person can see or check.
3. **Size:** a slice should fit in one sitting. If you cannot say how to check it in one sentence, cut it again.
4. **Order:** what proves the risky part goes early. Note what waits for what, and keep waiting chains short.
5. **People:** a slice that needs two people becomes two tickets, with the second waiting for the first. Name them by name and job.
6. **Say what is left out**, so nobody assumes it is coming.

Show the list before raising anything: number, title, person, waits for, how to check. When the owner agrees, raise each one with the skill `write-a-ticket`, listing the existing tickets first so nothing is raised twice.
