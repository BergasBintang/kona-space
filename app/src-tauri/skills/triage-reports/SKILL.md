# Sort the reports

The aim is that the worst thing is seen first, and that nothing gets lost.

1. **Collect** everything into one list. Keep a link to each person, because someone has to answer them. Keep personal details out of the list.
2. **Look at each one and name what it is:**
   - a bug;
   - a question (answer it: `support-reply`);
   - a request for something new;
   - something else (billing, abuse, spam).
3. **Merge duplicates,** and count them. Twelve people reporting the same thing is itself a finding. Check `list_tickets` for what is already known.
4. **Rank by harm:**
   - **Now:** data lost, money wrong, a security or privacy problem, nobody can use the main thing. Tell the owner straight away, and do not leave it in a list.
   - **Soon:** a main job fails for some people.
   - **Later:** annoying, with a way around.
   - **Maybe:** ideas and requests. Collect these for Kiki the Product.
5. **Decide the next step for each,** with a person. Bugs get a `bug-report` for the right person. Requests go to Kiki the Product with how many asked and in what words.
6. **Answer the people.** Everyone hears something, even if it is only "we have seen this".

Give a table: what, how many, how bad, next step, who. Then a short line on any pattern: what changed lately, what keeps coming up.
