# Critique a screen

Look at the real screen if you can, not only at its code. Ask for a screenshot if you cannot see it.

1. **The five-second test.** What does the eye land on first? Is it the most important thing? Can a stranger say what this screen is for?
2. **The job.** Walk through the one thing the person came to do. Count the clicks. Where would they stop or guess?
3. **Open `references/checklist.md`,** go through it, and note only what is really wrong.
4. **Rank.** Blocks the job, then confuses, then looks off. Say which is which.

For each finding give: where it is, what is wrong, who it hurts, and a concrete change. "Make the Save button the only filled button" helps. "Improve hierarchy" does not.

Also say what works and must be kept, so that a fix does not break it. Do not rewrite the whole look unless asked. Do not give taste as fact: when a thing is only your preference, say so.
